# About the Microsoft Defend the Tenant Challenge

The Microsoft Defend the Tenant Challenge is a hands-on security contest where participants strengthen a Microsoft 365 environment, apply real-world security recommendations, and create a practical security hardening plan for a fictional customer scenario.

This challenge is designed to help you build practical Microsoft 365 security skills while learning how to explain security decisions in a clear, customer-ready way.

## What You’ll Do

In this challenge, you will complete two phases:

| Phase | What You’ll Do |
|---|---|
| Phase 1: Secure the Environment | Work in a preconfigured Skillable Microsoft 365 tenant and implement required security controls based on Secure Score recommendations. |
| Phase 2: Security Hardening Plan | If you qualify, create a written security hardening plan for a fictional Microsoft 365 customer environment. |

## Phase 1: Secure the Environment

In Phase 1, you’ll connect to a preconfigured Skillable Microsoft 365 tenant and implement security controls based on Secure Score recommendations.

The control list may include tasks such as:

- Enabling multifactor authentication
- Blocking legacy authentication
- Configuring Microsoft Entra ID Identity Protection policies
- Limiting user consent to applications
- Securing Teams meeting settings
- Using least-privileged administrative roles
- Enabling self-service password reset

Phase 1 is the qualification round. Participants who successfully complete the required controls will advance to Phase 2.

## Phase 2: Create a Security Hardening Plan

In Phase 2, qualified participants will create a security hardening plan for a fictional Microsoft 365 customer.

Your plan should explain:

- What security controls you recommend
- Why each recommendation matters
- What risk each recommendation helps reduce
- How your recommendations improve the customer’s overall security posture

A strong submission should be clear, practical, well organized, and connected to the customer scenario.

## What Judges Will Look For

Submissions will be evaluated based on:

| Criteria | Weight |
|---|---:|
| Security Control Selection | 35% |
| Security Impact and Risk Reduction | 30% |
| Technical Understanding | 20% |
| Quality of the Recommendation | 15% |

Judges are looking for recommendations that are technically accurate, relevant to the scenario, clearly explained, and focused on meaningful security improvement.

Some restrictions apply. Please review the official rules for full eligibility details.

## Important Submission Guidelines

Your submission should be your own original work and should demonstrate safe, responsible, and practical security improvement.

Do not include:

- Confidential information
- Customer data or production tenant data
- Secrets, credentials, API keys, tokens, certificates, private keys, or connection strings
- Malware, exploit code, credential harvesting flows, persistence mechanisms, or unauthorized scanning tooling
- Offensive, illegal, or inappropriate content
